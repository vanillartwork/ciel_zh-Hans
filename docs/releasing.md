# 发布流程（维护者）

## 版本号

**两个版本号不要混为一谈：**

| | 例子 | 含义 |
|---|---|---|
| 补丁版本 | `v0.9.0` | 这个项目的版本 |
| 游戏版本 | `steam-2025-07` | 原游戏的版本 |

Release 标题用补丁版本，发布说明里单列一行写清楚适用的游戏版本。
混淆这两个，玩家就会把为别的游戏版本做的补丁装到自己机器上。

补丁版本按语义化的精神用：

- **主版本**：需要重新安装、或不兼容旧版的改动
- **次版本**：新译完一大块内容
- **修订版本**：修正错译、修 bug

## 步骤

### 1. 更新 `CHANGELOG.md`

按版本分节，标题写成 `## [0.9.0] - 2025-09-12`。
`release_notes.py` 会按这个格式抓取对应小节。

### 2. 更新 `docs/known-issues.md`

发布说明会原样引用它。

### 3. 如果重建过字体，同步字库清单

```bash
py -3 tools/export_charset.py
```

`data/charset.txt` 必须和实际发布的字形表一致，否则校验会放过
游戏里画不出来的字。

### 4. 确认数据干净

```bash
py -3 tools/validate.py
py -3 tools/selftest_validate.py
```

**必须零错误。**

### 5. 本机完整构建一次并实际试玩

```bash
py -3 tools/install.py --restore     # 先回到原版
py -3 tools/build.py --version 0.9.0
py -3 tools/install.py --apply
```

**一定要真的启动游戏看一眼。** 自动检查拦得住"控制码丢了"，
拦不住"字体锚点偏了三个像素"。至少确认：

- 标题画面正常
- 进入游戏能看到中文对白
- 菜单、道具说明、确认对话框正常
- 随便找个长对白，看看有没有超框

### 6. 打包安装程序

```powershell
cd installer
.\build-installer.ps1 -Version 0.9.0
```

产物在 `dist/`，带 `.sha256`。

### 7. 打标签

```bash
git tag -a v0.9.0 -m "简体中文补丁 v0.9.0"
git push origin v0.9.0
```

CI 会校验数据、生成发布说明、开一个**草稿** Release。

### 8. 补上安装程序并发布

CI 跑不了构建（服务器上没有游戏），所以：

1. 把 `dist/` 里的 `-setup.exe` 和 `.sha256` 附到草稿上
2. 核对发布说明里的校验和
3. 发布

## 发布说明里必须有

`release_notes.py` 自动生成，包含：

- 补丁版本、**适用的游戏版本**、日期、翻译进度
- 本次更新内容（来自 CHANGELOG）
- 安装要求（系统、正版游戏、磁盘空间）
- 支持的游戏文件 SHA-256（和安装程序核对的一致）
- 安装包自身的 SHA-256 核对方法
- 已知问题
- 非官方声明与禁止商业使用

## 游戏更新之后

见 [supported-versions.md](supported-versions.md)。

简单说：重新定位 exe 里的偏移、重新提取、看 `id` 和 `src` 哈希
还有多少对得上。剧本没大改的话，绝大多数译文能直接沿用。
