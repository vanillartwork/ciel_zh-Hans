# 支持的游戏版本

补丁按**特定版本的游戏文件**构建。版本对不上时，
安装程序会中止——这是故意的。

当前支持的版本记录在
[`data/game-versions.csv`](../data/game-versions.csv)：

| 版本 ID | 平台 | 说明 |
|---|---|---|
| `steam-2025-07` | Windows x64 | Steam 版 |

## 怎么确认自己的版本

```bash
py -3 tools/preflight.py
```

会打印三个关键文件的状态和校验和。

## 为什么要这么严

补丁替换的是 `PACK00_01.PAK`（1.7 GB）和 `PACK01.PAK`，
里面的偏移、条目顺序、加密 key 都和具体版本绑定。

把一个版本的封包装到另一个版本上，轻则文本错位，
重则游戏起不来。**宁可装不上，也不要装坏。**

exe 的情况更明确：字形表偏移 `0x8D08D0`、
引用它的 `lea` 指令在 `0x59656F`——这些都是硬编码的文件偏移，
换个版本就全错了。

## 游戏更新了怎么办

请开一个 [Issue](../../issues/new?template=bug.yml)，附上
`preflight.py` 打印的 SHA-256。

跟进一个新版本通常要做这些：

1. 确认封包格式没变（`test_roundtrip.py` 能验证）
2. 重新定位 exe 里的字形表偏移和那条 `lea`
3. 重新提取文本，看 `id` 有多少还对得上
4. 把新的校验和加进 `game-versions.csv`

如果剧本没大改，绝大多数 `id` 会保持有效，
译文可以直接沿用——`src` 哈希会告诉你哪些行真的变了。
这正是当初选择"哈希 + 稳定 ID"而不是按行号顺序存译文的原因。

## 别的平台

原作还有 PS Vita 版和在线版。本项目只针对 **Windows 的 DX 版**。

Vita 版的引擎和资源布局不同，工具链不能直接用，
但封包格式和脚本 CSV 的结构是相通的，
[reverse-engineering/](reverse-engineering/) 里的资料对移植有参考价值。
