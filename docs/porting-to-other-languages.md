# 移植到其他语言

封包读写和文本注入逻辑可复用，但现有目录、字体构建及校验规则仍包含简体中文约定。移植时须分别调整数据、字库和检查规则。

## 翻译数据

建议在独立分支或派生仓库中维护目标语言，先沿用现有 `data/zh-Hans/` 目录和 `zh` 列名：

1. 保留 `id`、`jp`、`src`、`ctl` 及长度限制。
2. 清空待译条目的 `zh`，将状态设为 `todo`。
3. 保留有技术理由的 `skip` 条目及备注。
4. 按目标语言维护术语表、字库清单和校验豁免。

这里的 `zh` 作为工具读取的译文列使用。若要更名或改用语言标签目录，须同步调整代码：当前 `validate.py`、`hydrate.py`、`dehydrate.py`、`merge_repo.py` 等仍按 `zh-Hans` 子目录读取。

`validate.py --data` 接受数据根目录；`merge_repo.py` 使用位置参数 `<数据根目录> <提取目录>`。这些参数本身不会改变语言子目录约定。

## 可复用组件

| 组件 | 用途 |
|---|---|
| `gustpak.py`、`repack_pak.py` | 封包读写 |
| `csvspan.py`、`import_text.py` | 按字段字节区间注入 |
| `export_text.py`、`export_exe_text.py` | 原文提取 |
| `patch_exe_strings.py` | 程序字符串替换 |
| `build.py`、`install.py`、`preflight.py` | 构建、安装与版本检查 |

目录约定、字库阶段及安装界面仍须检查和调整。

## 字库

`build_charset.py` 当前保留游戏需要的字形并加入 GB2312 字符集。移植时应统计目标语言实际使用的字符，调整候选集、字体与渲染参数。

拉丁字母或西里尔字母可先检查现有字形是否足够；韩文与繁体中文通常需要额外字形。是否能够容纳，以实际排布结果为准。

图集必须保持 8192×4096，UV 空间保持 4096×2048，字形按 4 像素块对齐。重建后从最终字形表导出 `data/charset.txt`。详见[字体资料](reverse-engineering/font-and-glyph-table.md)。

## 校验与排版

| 项目 | 调整要求 |
|---|---|
| 假名检查 | 确认是否适合作为目标语言的漏译检查 |
| `MAX_DIALOGUE_LINE` | 根据目标语言字宽与游戏内排版调整 |
| 术语表 | 更新标准译名与禁止译法 |
| `allow.csv` | 逐项复核，语言相关豁免不能直接沿用 |
| 字节与字符上限 | 保留游戏字段限制，以实际编码长度核对 |

`.bin` 和主程序文本通常以 UTF-8 字节数计长，环境设置文本另有字符限制。即使目标语言主要使用单字节字符，也须验证字段容量与实际显示。

## 验证

先通过数据校验与无改动重建，再检查游戏内长文本、菜单、缺字和安装还原。格式约束见[文件格式资料](reverse-engineering/README.md)。

通用工具改进可向本仓库提交 Pull Request，目标语言译文可在派生仓库独立维护。
