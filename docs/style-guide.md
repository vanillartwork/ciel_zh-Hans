# 翻译规范

译文应准确传达原意，符合角色语气，并满足游戏文本结构与显示限制。人名和专有名词以[术语表](../data/glossary/glossary.csv)为准。

## 技术要求

### 控制码与术语标记

```text
<CLBU> <CLY1> <CLY2> <OUT> <mess>  颜色或样式
<CR>                              文本框内换行
```

颜色与样式标记须原样保留，不得随意移动。例如：

```text
原文：<CLBU>ありがと、慰めてくれて……。
译文：<CLBU>谢谢你，安慰了我……
```

`<CR>` 常见于道具说明、帮助等文本。可根据中文长度减少，但不得增加；校验器对减少报告警告，对增加报告错误。

花括号用于标记词典术语。保留成对的 `{}` 和原有数量，括号内按术语表翻译：

```text
原文：{シェルノトロン}が暴走した
译文：{榭鲁诺特伦}失控了
```

### 占位符

`%s`、`%d`、`%5d`、`%-8s`、`$0$` 等由程序替换为动态内容。须完整保留，可按中文语序调整位置；格式宽度、数字和符号不得改动。

### 长度与换行

- 剧情对白建议每行不超过 24 个全角字符；超出时须核对游戏内显示。
- 实际换行会影响文本框排版，可适当合并，不应随意增加行数。`validate.py --strict` 可报告换行数量变化。
- 二进制字段的 UTF-8 译文长度须不超过 `max_bytes - 1`，保留一个字节作为结束符。
- 常用汉字通常占 3 字节。例如 `max_bytes = 12` 时，最多容纳 3 个此类汉字。
- `executable.csv` 采用原地覆盖，译文不得超过其 `max_bytes` 预算。
- 设置界面另有 `max_chars` 限制。

`status` 为 `skip` 的条目须保留原文，原因见 `note`。

## 中文表达

### 标点与数字

- 使用中文标点：`，。？！、：；“”‘’《》（）`。
- 引用使用 `“”`，省略号使用 `……`，破折号使用 `——`。
- 将日文 `「」`、`～` 等按语义和语气改为合适的中文标点。
- 数值、编号一般使用半角阿拉伯数字；用于排版的原文全角数字保留全角。
- 成语及固定表达使用惯常写法，如「一个人」「三三两两」。

### 人名与术语

遵循术语表中的标准译名与来源说明。`fixed` 词条不得未经讨论修改，`forbidden` 译法不得使用。

音译名分隔符使用 `・`（U+30FB），例如「依欧娜萨鲁・库库鲁鲁・普立薛尔」，与现有字库及译文保持一致。

### 角色语气

| 角色或身份 | 表达要求 |
|---|---|
| 依恩 | 温和有礼，避免网络用语；对玩家通常使用「你」 |
| 妮莉库 | 活泼、口语化，避免直接套用中文方言 |
| 喵洛基 | 适度保留句尾「喵」，根据原文控制频率 |
| 神官、军方人物 | 保留敬语层次，表达偏正式 |

避免加入原文没有的网络流行语、解释或情绪。译文应结合上下文调整语序，避免逐字对应日文句式。

### 简洁与自然

优先使用直接的动词和表达，减少不必要的「进行」「作为……的存在」「有着……的特征」等结构。对「～のだ」「～ということ」等句式，应传达语义或语气，无须机械补出对应成分。

完成后通读译文，检查歧义、重复、术语和行长。存疑处在 `note` 中说明，并将 `status` 设为 `needs-review`。
