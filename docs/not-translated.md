# 哪些内容还没有汉化

分三类：**刻意不译**、**暂时没做**、**不在补丁范围内**。

文本部分的数字来自 `data/`，随时可以用 `py -3 tools/validate.py` 复核；
图片部分是把 1,867 张贴图解码出来逐组看过之后写的；
视频部分是把脚本里 106 处视频播放逐一分析出来的。

---

## 一、刻意不译（不会改变）

### 屏蔽词表 — 290 行

`inc/globaldata/ngword_data.bin`

这张表用来过滤玩家输入的用户名、留言等。**翻译它会直接破坏过滤功能**：
换成中文之后，它既拦不住原本要拦的日文，也拦不住中文
（匹配逻辑不是为中文写的）。

### 可执行文件内的 59 条字符串

调试信息、动作计时标签、数据表字段名。玩家看不到，而且**引擎可能按名字
查找它们**，改了有让游戏出错的风险。

每一条为什么保留，都写在
[`data/zh-Hans/executable.csv`](../data/zh-Hans/executable.csv) 的 `note` 列里。
判断依据见 [reverse-engineering/executable-strings.md](reverse-engineering/executable-strings.md)。

### 演职员表

`res_x64/event_still/staff/`（28 张）

结尾名单上的是**真实人名与公司名**，按惯例不翻译。

## 二、暂时没做（欢迎接手）

### 图片里的文字

游戏一共 1,867 张贴图（1.34 GB）。逐组看过之后，**确认含有日文文字的只有两组**。

#### ① 依恩的状态标签 — 35 张 ★ 最值得做

`res_x64/ui_texture/yome_task/`（512×512，BC3/DXT5）

游戏里依恩在做事时，画面上会浮出一块牌子：

| | | | |
|---|---|---|---|
| 掃除中 CLEANING | 工作中 WORKING | 料理中 COOKING | ぼー… IDLING |
| 書き物 DRAWING | 着替え DRESSING | 外出中 AWAY | 食事中 EATING |
| 献立思考 THINKING | お昼寝中 SIESTA | 読書中 READING | お手洗い RESTROOM |
| 睡眠中 SLEEPING | 入浴中 BATHING | お片付け WASHING | ！！ |

**这是整个游戏里最常出现的未汉化内容**——正常游玩时几乎一直挂在屏幕上。

好消息是它们本来就是纯文字图，而且**已经带了英文**，
重画时可以照着现成的排版做。技术上不难：解码 BC3 → 重绘 → 编码回去 →
用 `repack_pak.py` 打包，图集尺寸不变，没有[字库那些坑](reverse-engineering/font-and-glyph-table.md)。

#### ② 教程说明图 — 33 张

`res_x64/event_still/tutorial/`（2048×2048，BC1）

这些是**带日文标注的游戏截图**：红圈、箭头、粉色说明文字，
外加一张手绘的「イオンの1日」作息时间轴。

这一组比较麻烦，有两个原因：

1. 标注是手写风格的，重画要花心思才不突兀；
2. **截图本身拍的是日文界面**——就算把标注译了，图里的菜单还是日文，
   和打完补丁的实际界面对不上。要做彻底，得重新截图。

其余贴图组（角色模型、夏尔头像、按钮图标、事件立绘、场景图）**都不含文字**，
不需要处理。

> 参考：Vita 版的英文补丁把图片也一并汉化了
>（其自述文件称 "The script and images are fully translated into English"），
> 所以这条路是走得通的，只是工作量在重绘上。

### 过场视频的字幕 ★ 可做，但工作性质不同

**原作的过场视频本身没有字幕**，其中相当一部分是有台词的。

引擎完全支持在视频上叠字幕——这一点是确认过的。
脚本命令 `EVENT_PROCESS_SET_MOVIE` 的注释写着
「ムービーをバックグラウンドで再生」：**视频是当背景层播放的**，
普通的对白系统照常画在上面。

磁盘上共 86 个视频文件，脚本引用到其中 82 个（另有 5 个 `MQ01`～`MQ05` 不由脚本播放；`sample_960x544_h264` 被引用但并未随游戏发行）。

按视频文件统计：

| | 数量 | 说明 |
|---|---:|---|
| 播放期间画过对白 | 19 | 证明这条路走得通 |
| 全程没有任何文字 | 63 | 其中不少是有语音的 |

无字幕的里面，最值得做的是：

- **`OP00`** —— 片头
- **`ExtendTalk01`～`07`** —— 与《Ar nosurge》联动的**语音剧**，
  单个 57～86 MB。脚本（`linkarno_sleep01`～`07`）长这样：

  ```
  SET_MOVIE   DLC/ExtendTalk01.usm
  WAIT_TIME   1900          ← 整段只有这一行，没有任何文字
  UNSET_MOVIE
  ```

  把中间那行拆成「对白行 + WAIT_TIME」的序列，字幕就出来了。

- `CIEL_JISO_END_L/M/S` —— 结局相关

> Vita 版的英文补丁做的就是这件事，其改动清单里写着
> **"All videos have been subtitled"**，
> 以及为恢复的语音「given translations via subtitles」、
> 给语音留言补字幕。所以这是**主动增加原作没有的内容**。

**为什么还没做：** 这和"翻译现成文本"是两种活。

1. **没有原文可译。** 得先把日语语音**听写**出来——72 段视频。
2. **要对时间轴。** 每句字幕插在哪、停多久，都要逐段调 `WAIT_TIME`。
3. **要往脚本里插入新行。** 本项目的注入是
   [按字节区间替换现有单元格](reverse-engineering/event-script.md)，
   保证空改动逐字节相同；插行是另一套操作，`csvspan.py` 需要扩展。

技术上没有拦路虎，但这是一个独立的子项目。有兴趣的话建议单独开 Issue 讨论。

> 唯一可能真的需要重新压制的是 `ME12_telop.wmv`——
> 「テロップ」就是画面上的字幕条，它的文字很可能是压进画面的。
> 这一个需要先确认。

### 夏尔（宠物）的名字 — 1,611 个 ✅ 已完成

`inc/sharl/sharl_name_data.bin`（296 条记录 × 72 字节，名字在 `+0x00`）
`inc/sharl/sharl_npcrating_data.bin`（1,596 条记录 × 536 字节，名字在 `+0x1DC`）

前者是**取名时可选的 294 个名字**，分片假名、平假名、汉字三种风格；
后者是 **1,596 只 NPC 夏尔的档案**，每只带一个名字。

这批数据一度被本文写成「拼接用的词根，字节上限 4～6 字节，译不了」。
**那是错的**：它们是完整的名字，每个都住在**独立的 32 字节字段**里，
可用 31 字节 = 10 个汉字。之前量出来的「10 字节」是打包工具留下的垃圾
（短名字盖在长名字上没清尾巴）骗过了提取器；`tools/export_text.py` 的
`BIN_SCHEMA` 现在给这两个文件写明了记录格式，预算已经恢复正常。

而且这 1,611 个名字是完全可拆的：npcrating 里的 1,434 个名字，
**每一个**都是「名字池里的某个名字 + 57 个后缀之一」（或者不加后缀）。
也就是说，**翻 294 个基名 + 57 个后缀就够了**。

其中 9 个名字已经有译文了——它们在别处也是个词（`ピンク` 是体色、`蓮花` 是衣装、
`みさき` 出现在初期评价里），译文按字符串共享，所以顺带被填上了。
`みさき→海角`、`プール→泳池`、`コーラス→和声` 当宠物名都很怪，值得复核。

真正需要拿主意的是后缀：片假名后缀（サー、ニル、ドン…）是纯装饰音没有意义；
平假名后缀（こ、たん、っぺ、にゃ…）是日语给宠物起小名的叠音后缀，
中文没有对应物；汉字后缀（亭、丸、之助、ヶ崎…）可以基本照搬，
但 `々` 是「重复前一个字」，中文没有这个符号，必须改写。

### 夏尔档案词条 — 16 条 ✅ 已完成

## 想接手图片汉化？

从状态标签那 35 张开始，性价比最高。

需要的工具仓库里都有：

- `tools/gustpak.py` —— 从封包里取出 `.g1t`
- `tools/bc1.py` —— BC1 编解码（BC3 需要自己补，格式标记是 `0x5B`）
- `tools/repack_pak.py` —— 打包回去

G1T 容器的头部结构写在
[reverse-engineering/font-and-glyph-table.md](reverse-engineering/font-and-glyph-table.md)：
`0x25` 是格式（`0x59`=BC1、`0x5B`=BC3、`0x01`=RGBA），
`0x26` 高低半字节分别是高、宽的 2 的幂次，像素数据从 `0x2C` 开始。

动手前建议先开一个 Issue 说一声，免得撞车。
