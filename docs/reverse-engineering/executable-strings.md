# 可执行文件字符串

中文 | [English](executable-strings.en.md)

`CielnosurgeDX.exe` 的 `.rdata` 中包含确认对话框、网络提示、菜单及状态描述等 UTF-8 字符串。`executable.csv` 有 377 条基础记录，其中 318 条已有译文；0.9.8 的 `exe_sited.csv` 另有 70 条补译。摘要来源移到显示层后，当前地址清单保留 38 个写入位置（37 个 `display`、1 个 `persisted`）；译文记录数不等于原位写入数。

## 提取与定位

`tools/export_exe_text.py` 扫描以 `\0` 结尾的 UTF-8 字符串，以假名和 CJK 字符特征筛选候选文本。

扫描须接受完整 UTF-8 多字节序列。过窄的正则范围会在 `※`、`★`、全角字符等位置截断字符串，导致替换时无法匹配。

## 替换约束

`patch_exe_strings.py` 在原位置覆盖字符串，保留现有指令引用：

- 译文的 UTF-8 字节数不得超过原文预算。
- 剩余空间填 `\0`。
- 匹配要求前后均为 `\0`，防止误替换其他字符串中的片段。
- 按原文长度从长到短处理。
- 所有匹配都基于修改前的输入，避免把刚写入的译文再当成另一条日文替换。
- 字符串替换阶段不改变文件大小或 PE 节表。

例如，独立的「食器洗い」不应匹配较长说明中的同名片段。

## 保留项与数据引用

59 条保留项包括调试或断言信息、动作计时标签、数据表字段名和开发期测试文本。理由记录在 `data/zh-Hans/executable.csv` 的 `note` 中。

修改前运行：

```powershell
py -3 tools/check_exe_text.py --archives
```

该工具检查运行时数据中是否存在相同的完整字段，结果须人工判断：

| 命中位置 | 判断要点 |
|---|---|
| `.inc` | 角色映射表族由游戏运行时读取；其他表中出现同名文本、注释或枚举标签，不能单凭命中认定为键 |
| 剧本 | 对白中出现相同词语不足以证明程序依赖 |
| `.gbd` | 区分记录 ID、事件 ID 与显示字段；梦世界表布局见[GBD 文档](dream-tables.md) |
| `.xml` | 区分注释、显示文本与结构字段 |
| `.bin` 完整字段 | 确认其为显示内容、独立副本还是查找键 |

既有复核中，「トイレ」在 `point_data.bin` 中属于显示名，实际键为 `ePOINT_YOME_TOILET`；「HymPが足りません。」在错误信息表中为独立文案副本。无法确认用途的字段名继续保留。

## 按地址授权的字符串

`patch_exe_strings.py` 会改写所有同文副本，只适合确认在整个程序里都只作显示的文字。导出工具因此跳过了两类字符串：含 `%s`/`%d` 的格式串（被当作调试信息），以及只有汉字没有假名的词（被当作乱码）。这两类改由 `exe_sites.py` 处理：

- 译文按词记录在 `data/zh-Hans/exe_sited.csv`。依恩状态名等已有译文的条目沿用 `executable.csv` 中的 id。
- 写入权限按地址记录在 `data/exe-sites/<版本>.csv`：每行是一个 RVA、原文字节数、原文摘要、用途（`display` 或 `persisted`）及证据。同一日文在别处的副本不因此获得写入权限。
- 构建时先在未修改的程序上核对全部地址（原文字节、所在节、容量、区间重叠），全局写回再跳过这些 id，最后一次写完。全局写回若改到了授权地址，构建会停止。
- 格式串的转换序列（含标志、宽度，以及 `%%`）必须与原文一致，且字节不增加，所以格式化结果不会比原版长。被当作格式串使用的文字（章节名、状态名）不得新增 `%`。
- `persisted` 表示文字会写进存档，校验器要求保留换行、全角冒号「：」和空格的个数。当前清单中仅游玩时间格式保留这一用途；其他摘要来源已经撤去原位写入授权。

判断一个地址能否授权，看这个地址的**每一处引用**：

| 证据 | 结论 |
|---|---|
| 只作为 `sprintf`/`snprintf`（0x42e130、0x4bc9d0、0xa2f630、0x4314c0）的格式参数 | 原文本身不被比较；结果去向决定是否有用 |
| 交给设字函数 0x7cc920（内部调用 `ACSpriteText` 的 setter）、对话框 0x7cda30/0x7ce5e0、弹窗消息队列（+0x2720，经 0x5af8d0） | 显示 |
| 交给按列名读表 0x79b4f0，或由 memcmp 0xa03bc0 比较 | 查找键，不改 |
| 与动作计时表等共用同一份字节、用途未查全 | 不原位改，走显示层整句替换 |

几处已查明的用法（steam-2025-07）：

- 依恩状态表 0xc6c8e0（30 条，步长 0x98）按数字编号建映射；按名查任务的 0x75a490 比较的是英文 `TASK_*` 标签，日文名只用于显示。「起床」与动作计时表分组名共用字节，所以不原位改。
- 章节名由 0x4ca520 以内联拷贝建立「事件编号 → 章节名」局部表，按 `ME01_00` 等事件编号查找。
- 「名前」「基準X」「嫁X回転」等是数据表列名，「回復量」「創造力」「指導力」「不可」由 memcmp 比较，均保留原文。

### 备忘录

`EVENT_PROCESS_WRITE_MEMO` 的文字在写下时存入存档，每条备忘的存储有长度上限：一条 104 字节的中文备忘在 92 字节处被截断（按完整字符）。程序内的确切上限尚未定位，观测值说明在 92～94 字节之间；原版最长的三条日文备忘为 95 字节。

从 0.9.8 起，`build_patch.py` 排除 `kind=memo` 的注入项，脚本里的备忘参数保留日文。显示表从脚本译文生成整句映射，同时收录 LF 与 CRLF 形式；带控制标签的备忘不作为普通整句收录。脚本条目数、换行变体数和去重后的映射数不同，不应混用。

0.9.4～0.9.7 的中文备忘、准备版写入的当前中文，以及原版日文可能留下的截断文本，由 `old_memos.py` 补充映射到当前译文。候选包括完整旧文，以及按 92/93/94 字节在 UTF-8 字符边界截断的文本；这三个值是对实测上限的候选，不是已定位的格式常量。有冲突或可能误认完整备忘的候选会被跳过。历史译文由 `tools/dev/gen_memo_history.py` 从发布标签生成到 `data/zh-Hans/_memo_history.csv`。匹配发生在显示时，不改写存档。

保留日文消除了译文变长带来的新增截断风险，但原文本身仍可能超过存储上限。显示替换也不保证文本框能容纳任意长度，仍须检查排版。

备忘框按每行最多 11 个全角字符、最多 3 行复查。维护工具 `tools/dev/rewrap_memos.py` 需要已有的脚本提取结果，默认只检查，`--apply` 才写译文。它不是通常对白的换行规则。

## 构建顺序

1. `build_font.py` 从原始主程序生成字形表补丁，新增 `.fontex` 节。
2. `exe_keys.py` 筛出需保留的候选词，`patch_exe_strings.py` 只写放行项。318 条已有译文并不等于原位改写 318 条。
3. `exe_sites.py` 写入地址清单授权的字符串；地址在第 2 步之前核对。
4. 默认构建最后用 `pe_loader.py` 添加显示层入口；DLL 与替换表单独安装。

若先替换字符串，再从原始程序重建字库，前一步修改会被覆盖。
