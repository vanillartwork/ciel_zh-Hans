# 梦世界数据表（GBD）

中文 | [English](dream-tables.en.md)

0.9.8 将 `inc/dream/` 中四类 `.gbd` 接入翻译流程。每类有 12 个章节文件，共 48 个；`ruin_control_data` 和 `ruin_parts_data` 不在修改范围内。

这些文件是定长记录数组，没有单独的文件头。后续章节会再次包含早期章节的记录，因此一条译文通常有多个写回位置。布局定义见 [`gbd_text.py`](../../tools/gbd_text.py) 的 `FAMILIES`，适用于 `steam-2025-07`。

## 已处理字段

偏移相对于记录开头，以下数字均为十进制。

| 文件族 | 记录字节数 | 翻译字段及偏移 |
|---|---:|---|
| `dream_area_data` | 304 | 进门副标题 `+28` |
| `event_history_data` | 844 | 剧中时间 `+48`、标题 `+104`、概要 `+244` |
| `ruin_data` | 352 | 地点名 `+84` |
| `ruin_restore_data` | 336 | 修复对象名 `+124` |

记录 ID、事件 ID 和部件 ID 不翻译。`ruin_data` 的平假名读音从 `+140` 开始，0.9.8 将其原文占用的字节清零，使地点名不再附带日文读音。这是单独的清空规则，不是译文字段；没有译文时也会执行。

## 写入范围

字符串采用 UTF-8，以 NUL 结束。NUL 后经常有非零残留，不能把到下一字段的距离都当成译文容量。

- 译文最多占用原日文的字节数，缩短后在这段范围内补零。
- 原有终止符及其后残留不动，记录长度和文件长度不变。
- 文件长度不整除记录长度、字段读不到终止符、译文超长或含 NUL 时，停止处理。
- 字段的读取上限与可写容量不同。`dream.csv` 的 `max_bytes` 是原文字节数加一，校验时为结束符留一字节。

因此，不能把其他 `.bin` 表“填满整个定长字段”的规则直接用于 GBD。

## 译文与重复记录

[`dream.csv`](../../data/zh-Hans/dream.csv) 按“表族＋字段＋原文摘要”标识译文。当前有 781 条：12 条副标题、552 条 HISTORY 时间／标题／概要、70 条地点名、147 条修复对象名。

导出时保留每条原文的成员路径、记录名、字段和偏移；写回时更新所有对应位置。不能只改最早章节的文件，也不能因日文相同就合并不同字段的用途。

## 验证

不需要游戏的合成记录自检：

```powershell
py -3 tools/selftest_gbd_text.py
```

本机用原始封包和构建导出的译文核对改动范围：

```powershell
py -3 tools/gbd_text.py verify "D:\Test\Backup\PACK01.PAK" build/work/dream_text.csv
```

该命令不写封包。结构检查通过后，仍需实机检查进门副标题、HISTORY 长概要与翻页、废墟名称显示。读音已被清空，如发现列表顺序异常，也应记录场景复核。
