# 字体图集与字形表

以下偏移适用于项目记录的游戏版本，其他版本须重新定位。

## 图集

```text
封包内路径  res_x64/font/fot-skipstd-b_0.g1t
容器        GT1G0600
格式        0x59，BC1 / DXT1
物理尺寸    8192 × 4096
UV 空间     4096 × 2048
```

物理坐标为字形 UV 坐标的两倍。R 通道固定为 255，覆盖度保存在 G/B 通道；编解码时须保留这一约定。

G1T 中，`0x25` 为格式标记，`0x26` 的高、低半字节分别表示高度、宽度的二次幂指数，像素数据从 `0x2C` 开始。相关格式标记包括 BC1 的 `0x59`、BC3 的 `0x5B` 和 RGBA 的 `0x01`。

## 字形表与描述符

原字形表位于主程序文件偏移 `0x8D08D0`，共 8,344 条，每条 28 字节：

```c
struct Glyph {
    u32 code;        // UTF-8 字节按大端组合的整数
    i16 x, y, w, h;  // UV 坐标及尺寸
    i32 ox, oy;      // 绘制偏移
    i32 adv;         // 步进
    i32 pad;
};
```

`code` 不是 Unicode 码点。引擎按此值二分查找，新表须保持排序。

描述符位于 `0x8D08A0`：

```c
struct FontDesc {
    u16 uv_w, uv_h;   // 4096, 2048
    u32 pad;
    char *texture;
    u64 count;        // 引擎仅读取低 16 位
};
```

计数字段位于 `0x8D08B0`，由 `movzx r8d, word [rdx+0x10]` 读取，上限为 65,535。字形表的 RIP 相对引用位于文件偏移 `0x59656F`：

```asm
lea r9, [rip+disp32]      ; 4C 8D 0D xx xx xx xx
```

## 扩展方式

原表含 6,718 个汉字，其中游戏文本使用 2,243 个。构建时移除未使用的原字形，为 GB2312 的 7,445 个字符腾出空间。现有构建记录为 9,351 个字形、约 89.3% 图集占用率。

扩展表写入新增的 `.fontex` 节（VA `0x145C000`），同时更新表引用与 u16 计数。原 12 个节之后的节表空间可容纳新增节头。

## 尺寸与对齐

- 图集保持 8192×4096，UV 空间保持 4096×2048。引擎的 UV 缩放不随描述符尺寸自动调整。
- 字形按 4 像素块分配，与 BC1 的 4×4 压缩块一致，同时保证物理坐标除以 2 后为整数。
- 新图集与新字形表须成套安装。引擎不读取散文件覆盖，图集须写入 `PACK00_01.PAK`。

当前图集长度保持 16,777,260 字节，可通过原地修改写入封包，无需完整重建。

## 字体与渲染参数

GB2312 汉字统一使用微软雅黑 Bold 绘制，假名、拉丁字母、标点及日文专用汉字按构建规则保留原字形。源字体无法绘制的字符回退到原字形。

现有参数为 `msyhbd.ttc`、55 px、`ANCHOR_X = 67`、`ANCHOR_Y = 58`。更换字体须重新校准偏移，并在游戏中检查字重与基线。

## 原始文件与校验

`pristine_exe()` 要求原始主程序有 12 个节，并优先使用 `Backup/` 中的原件，避免重复添加 `.fontex`。图集也须来自正确的原始资源；必要时先还原游戏再构建。

重建后运行 `tools/export_charset.py` 更新可显示字符清单，并验证对白、菜单、日文保留项及长文本显示。
