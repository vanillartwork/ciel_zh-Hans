# 字体图集与字形表

这是整个项目技术上最容易出错的一块。下面既写结论，也写踩过的坑。

## 图集

```
封包内路径  res_x64/font/fot-skipstd-b_0.g1t
容器        GT1G0600
格式        type 0x59 = BC1 / DXT1
物理尺寸    8192 × 4096
UV 空间     4096 × 2048          （字形坐标 × 2 = 物理坐标）
```

**R 通道恒为 255，覆盖度存在 G/B 通道。** 解码和重新编码时
只处理覆盖度平面，R 固定写 255。

## 字形表

编译进 exe，文件偏移 **`0x8D08D0`**，原本 **8,344** 条，每条 28 字节：

```c
struct Glyph {
    u32 code;        // UTF-8 字节按大端打包
    i16 x, y, w, h;  // UV 空间坐标
    i32 ox, oy;      // 绘制偏移
    i32 adv;         // 步进
    i32 pad;
};
```

`code` 不是码点，是**该字符 UTF-8 编码的字节按大端拼成的整数**。

字体描述符在 **`0x8D08A0`**：

```c
struct FontDesc {
    u16 uv_w, uv_h;   // 4096, 2048
    u32 pad;
    char *texture;
    u64 count;        // 实际按 u16 读，见下
};
```

字形数量在 **`0x8D08B0`**，引擎用

```asm
movzx r8d, word [rdx+0x10]
```

读它——也就是当作 **u16**，上限 65535。

**引擎对这个数组做二分查找**，所以新表必须按 `code` 排序。

整个 exe 里只有**一处** RIP 相对引用指向这张表，
在文件偏移 **`0x59656F`**：

```asm
lea r9, [rip+disp32]      ; 4C 8D 0D xx xx xx xx
```

## 扩容

GB2312 有 7,445 个汉字。原表 8,344 条里有 6,718 个汉字，
但这个游戏实际只画其中 2,243 个。

所以：**扔掉用不到的 4,475 个汉字**，腾出的位置装 GB2312。
最终 9,351 条，图集占用率 89.3%，GB2312 覆盖 7,445/7,445。

新表装不下 `.rdata` 里原来的位置，于是：

1. 新建一个 `.fontex` 节（VA `0x145C000`）
2. 把 `0x59656F` 的 `lea` 重新指向它
3. 把 `0x8D08B0` 的 u16 计数改成新的条数

12 个节的节表后面正好有 424 字节的空闲，够放第 13 个节头。

## 三个坑

### 一、图集尺寸不能改

最初的做法是把图集放大到 8192×8192，并把描述符的 UV 字段
改成 4096×4096。结果**满屏乱码**。

原因：**引擎的 UV 除数不是从描述符里读的。** 它在别处写死了，
所以描述符里写什么都没用，每个字形都按两倍高度采样。

结论：**图集必须保持 8192×4096，UV 空间保持 4096×2048。**
腾地方只能靠删掉用不到的字形。

### 二、字形坐标必须按块对齐

第二次尝试仍然乱码，但错位方式不同。

原因是打包器给新字形分配了**奇数尺寸**，导致后续字形的 x/y 也变成奇数。
而 UV 坐标 = 物理坐标 / 2，`x//2` 在奇数上会截断，
于是从某个字形开始，后面全部偏移一个像素。
测下来 40% 的保留字形对不上位置。

解决：**按 4 像素块对齐分配**（`BLK = 4`）。
4 既是 BC1 的块大小（避免两个字形挤进同一个 4×4 块），
也保证除以 2 之后仍然落在整数网格上。

修正后，保留字形的像素误差中位数 1.64，400 个抽样里没有一个超标。

### 三、散文件不生效

前两个坑都修好之后**还是乱码**。

真正原因是：**引擎只读封包，散文件完全不生效。**
当时 exe（新字形表）已经装进去了，但图集和文本还放在散文件里，
于是新表配旧图集——当然对不上。

必须重打包 `PACK01.PAK` 和 `PACK00_01.PAK`。

## 字体一致性

一开始只补画缺失的 GB2312 汉字，保留原字体已有的汉字。
结果中文句子里**粗细不一**——原字体 FOT-Skip Std B 和补画用的
微软雅黑 Bold 笔画重量不同，混在一句话里很明显。

改成：**所有 GB2312 汉字统一用雅黑重画**，
只有假名、拉丁字母、标点和日文专用汉字保留原字形。
这样中文句子内部始终是一种字体，日文部分也保持原貌。

渲染参数：`msyhbd.ttc` @ 55px，`ANCHOR_X = 67`、`ANCHOR_Y = 58`。
这两个锚点是校准出来的，让新字形的墨迹框和原字形对齐到一个像素以内。
换字体需要重新校准。

雅黑画不出来的字符（比如表意空格）回退到原字形。

## 从未打补丁的 exe 出发

`build_font.py` 必须读**未打补丁**的 exe，否则会叠加第二个
`.fontex` 节。`pristine_exe()` 要求镜像恰好有 12 个节，
并优先使用 `Backup/` 里的那份。

同理，图集要从 `Backup/PACK00_01.PAK` 读，
否则读到的是上一版补丁的中文图集。
