# 剧情脚本格式

`inc/event/res/**/*.txt` 使用带 BOM 的 UTF-8 CSV，记录换行为 CRLF。文件扩展名不代表纯文本段落格式。

## 字段

列号从 0 开始：

| 列 | 内容 | 处理方式 |
|---:|---|---|
| 11 | **角色键**（同时被当作名牌显示） | **不可翻译** |
| 12 | 对白正文 | 翻译 |
| 13 | `EVENT_PROCESS_*` 指令 | 保留 |
| 9、15、18、20、21、22 | 开发者注释 | 保留 |

部分指令的参数也包含可显示文本，提取范围由 `tools/export_text.py` 的 `CMD_TEXT` 定义。

对白字段内的实际换行对应游戏中的分行。译文可适当合并行数，增加行数则须验证文本框容量。

## 控制码

| 标记 | 含义 | 处理方式 |
|---|---|---|
| `<CLBU>`、`<CLY1>`、`<CLY2>`、`<OUT>`、`<mess>` | 颜色或样式 | 保留内容与作用位置 |
| `<CR>` | 文本框内换行，常用于道具及帮助文本 | 不得增加数量 |
| `{术语}` | 词典索引标记 | 保留花括号，翻译内部术语 |

## 写回方式

`tools/csvspan.py` 定位目标字段的字节区间，注入时只替换对应范围。不要重新序列化整个 CSV，否则可能改变原文件的引号、BOM 或换行。

无改动注入须与输入逐字节一致，验证命令见[格式资料索引](README.md#关键约束)。

## 说话人

第 11 列**不是**显示用名牌，而是角色键，只是同时被当作名牌显示。

`inc/event/charanamemap.inc` 按这个字符串索引模型，且区分尾随全角空格：
`"イオン"` 是普通模型，`"イオン　"` 是 Q 版模型，`"ネイ"` 与 `"ネイ　"` 亦为两个角色。
放置角色的行用它指定放谁；其后的每一行——**包括对白行**——用它指明该行的台词与表情
属于已放置角色中的哪一个。第 8 列的 `FS_CRY` 是通用值，需与角色键组合才能解析为
`charafacestancemap.inc` 中的 `PC00_FS_CRY`。

翻译它不会表现为译名错误：查找直接失效，于是角色不出现、动作与口型不变化、
镜头没有目标、需要定位的互动环节卡死。本项目 0.9.4 与 0.9.5 即因此出现该问题。
在能把「键」与「显示标签」分开之前，名牌保持日文。

`EVENT_PROCESS_CHANGE_DISPLAY_NAME` 同理：参数 1（第 14 列）是角色键，
参数 2（第 15 列）才是要显示的标签，只有后者可翻译。

`export_text.py` 仍将角色键及出现频次导出到 `glossary_speakers.csv` 作为参考（便于译者知道谁在说话），但**不注入**。`tools/selftest_inject.py` 会校验这一点。
