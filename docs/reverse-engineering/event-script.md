# 剧情脚本格式

`inc/event/res/**/*.txt`——扩展名是 `.txt`，内容其实是
**带 BOM 的 UTF-8 CSV，CRLF 换行**。

3,046 个文件，约 7.7 万行可翻译文本。

## 列

从 0 开始数：

| 列 | 内容 | 翻译？ |
|---:|---|---|
| 11 | 说话人名 | ✅ 按术语表 |
| 12 | **对白正文** | ✅ 主要目标 |
| 13 | `EVENT_PROCESS_*` 指令名 | ❌ 绝对不能动 |
| 9, 15, 18, 20, 21, 22 | **开发者注释** | ❌ 不要翻译 |

那几列注释是最容易搞错的地方：它们内容是日文，看起来很像该翻译的文本，
实际是开发期写给自己看的备注，玩家永远看不到。
翻译它们没有收益，还会让 diff 变得难读。

第 12 列里的**换行就是游戏里的换行**。中文更短，
把原文三行并成两行没问题；**多加一行则可能超出文本框**。

## 控制码

### 颜色/样式标记

```
<CLBU>   <CLY1>   <CLY2>   <OUT>   <mess>
```

**总是出现在行首**，作用到整行。原样保留。

### `<CR>`

文本框内换行。**对白里不会出现**——只出现在道具说明、
帮助文本、邮件正文这类字段里。

### `{}`

```
{シェルノトロン}が暴走した
```

游戏用花括号标出可以查词典的术语。**括号保留，里面的词翻译。**
括号丢了词典功能就失效。

## 为什么要按字节区间替换

往回写的时候，**不要用 `csv` 模块重新序列化整个文件**。

原因是原文件里有些字段带着并非必要的引号，
`csv` 模块重写时会把它们规范化掉。2,958 个脚本文件里有 19 个
会因此和原文件产生差异——虽然语义相同，但这意味着
"没改动的文件"也不再是逐字节相同，往返验证就失去意义了。

`tools/csvspan.py` 扫描出每个字段的**精确字节范围**，
注入时只替换需要替换的那一段，其余字节原样保留。

验证过：对全部 2,958 个脚本做"替换成原值"的注入，输出与输入完全一致。

## 说话人

说话人名（第 11 列）同时是**语音和立绘的查找键**吗？

不是。角色标识另有 `CHARA_*` 常量，见 `inc/event/charanamemap.inc`。
第 11 列是显示用的名牌文本，可以安全翻译。

`tools/export_text.py` 会顺带统计每个说话人出现的次数，
输出到 `glossary_speakers.csv`，用来确定主要角色的译名。
